summary: Known limitations and defects of the virtual collection sketch
description: Known limitations and defects of the virtual collection driver sketched in `_.ts`, ahead of its merge into `@metreeca/gate`.
---

The virtual collection driver in [`_.ts`](_.ts) serves a collection with no record stored at its address. Its members
are the resources linked to a stored resource along a path of properties, as `/resources/` lists the resources whose
dataset belongs to the dataset catalogue. The sketch is to be merged into `@metreeca/gate/driver` once the issues
below are settled, so that virtual collections are served by `driver()` alongside stored ones.

# Limitations

- **Backlinks Required**: every property along the path needs a backlink on the resource it points to, matching its
  `forward` or `reverse` mapping. The driver fails as it is enabled where a backlink is missing.
- **Per-Step Pagination**: sorting (`^`), offset (`@`) and limit (`#`) apply within each resource along the path
  rather than across the flattened members, so a page of `/resources/` holds up to `#` resources from every dataset.
- **Implicit Truncation**: the server `limit` caps every step along the path, client steps and backlink steps
  alike. With the current limit of 100, `/resources/` returns at most 100 resources per dataset, and 100 datasets.
- **Per-Step Aggregation**: grouped projections, such as counts per university, are computed within each dataset.
  The response holds one row per dataset and group, unissued datasets included, so clients must sum the rows.
- **Hidden Depth**: backlink steps are added to the server `depth`, so that clients get the depth they would get on
  a stored collection. Their cost is not bounded by the scope, and grows with the length of the path.
- **No Server Template Bounds**: the server `model` is merged over the client query key by key, without the bounds
  that `driver().lookup({ model })` enforces. A server criterion replaces a client one on the same key rather than
  narrowing it, and the server can't cap the page size or withhold hidden properties.
- **No Default Expansion**: an empty or criteria-only query returns bare member references, rather than the default
  view described by the member shape, so clients must state the properties they need in a template.
- **Collection-Only Queries**: only the virtual collection entry of a client template is honoured. Other entries,
  `id` included, are ignored, and the response always states `id` and the collection alone.
- **No Review Hook**: the retrieved collection is served as is, with no way to withhold it per request.

# Defects

- **Unanchored Collections**: keep retrieves only members linked from the entry, so a collection defined by its member
  shape and server template alone, as `/resources/` now is, answers `501 Not Implemented` until keep supports it.

- **Gate Internals**: the store, base and scope are read through the private `@metreeca/gate:*` application settings.
  If Gate renames them, the driver breaks without warning: it fails with `undefined application store`, or it falls
  back to the request host for the base and to an unbounded scope for depth and page size, with no error raised.
- **No Not Found Status**: a missing stored resource yields an empty collection rather than `404 Not Found`.
- **Issued Filter Workaround**: `/resources/` selects resources in issued datasets through a `">=dataset.issued"`
  lower bound, until the query language supports absence tests ([qest#26](https://github.com/metreeca/qest/issues/26)).
