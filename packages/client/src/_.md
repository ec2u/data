# Tile Widgets

- **Card** – `@metreeca/tile` has no counterpart of `TileCard`. ec2u/data shows each dataset as a two-column row:
  - a fixed side column (7.5em) with the member count as a tag at the top and the short name (`alternative`) below,
    both right-aligned;
  - a main column with the title link at the top and the description below;
  - 1em between rows, 1em column gap, 0.5em row gap.
- **Paging** – `useCollection` takes no offset or limit, so `More` cannot drive incremental loading. This does not
  matter for datasets (about 6 items) but blocks parity for longer collections.

Until the card exists, the page lists each dataset as a plain list item: its title link followed by the member count.

# Data Model

- **Projection model** – the page retrieves each dataset through a single projection, `"dataset="` expanded with a
  template next to `"size=count:resources"`, since a typed model cannot mix template fields with bindings.
  - The store mishandles empty-path bindings ([metreeca/keep#21](https://github.com/metreeca/keep/issues/21)): until
    that is fixed, rows lack the `dataset` cell and the page lists nothing.
  - Projected rows are typed `Optional<Value>`, so the view narrows `dataset` and `size` with type guards; these are
    provisional until a typed query DSL lands ([metreeca/keep#15](https://github.com/metreeca/keep/issues/15)).
- **Description** – `description` is rendered as a plain paragraph under the title, pending the card.
- **Short name** – `alternative` is retrieved but not rendered yet, pending the card.
