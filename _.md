# Java and App Engine Cleanup

The Java stack stays reachable through the `java-legacy` tag. Until `main` and `next` move to Cloud Run, it keeps
running on App Engine as the shared GraphDB user `data-server`, which reads and writes `data-main` and `data-next`.

- [ ] Port the App Engine cron schedule (`java-legacy:src/main/appengine/cron.yaml`) to Cloud Scheduler jobs on the
	loader endpoints of each environment
- [ ] Promote `edge` → `next` with a merge commit, never a squash, once the `next` Cloud Run resources and the
	`data-next-{service}` GraphDB users exist; move `next` from the `gae-deploy.yml` to the `deploy.yml` triggers in
	the same commit
- [ ] Promote `next` → `main` the same way, with the `main` resources and `data-main-{service}` users in place
- [ ] Delete the App Engine versions `main`, `next` and `work`, then disable the App Engine application
- [ ] Delete the `GCP_SA_KEY` and `GCP_PROJECT` repository secrets, then the `github` service account behind them
	(user key `3ef2b9b5…` from 2022; App Engine admin, Cloud Build editor, Cloud Scheduler admin, Storage admin and
	service account user roles on the project)
- [ ] Delete the `server` service account (Secret Manager accessor, Storage object admin), unused by the Cloud Run
	layout
- [ ] Drop `roles/editor` and `roles/secretmanager.secretAccessor` from the default compute service account, and
