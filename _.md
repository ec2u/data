---
title: Cloud Run Migration
summary: What is left to move the Knowledge Hub from App Engine to Cloud Run, environment by environment
---

The phases run in order: each environment moves to Cloud Run before the next one is promoted, and App Engine is
retired only once `main` runs on Cloud Run. The Java stack stays reachable through the `java-legacy` tag; until then it
keeps running on App Engine as the shared GraphDB user `data-server`, reading and writing `data-main` and `data-next`.

# 1. Deploy `edge`

On hold until the first deployment is due.

- [ ] Provision the shared resources `deployment-manager` lists as missing (`deployer` bound to `ec2u/data`, `images`
	registry, `github` pool, `scheduler` account), then the `edge` runtime accounts
- [ ] Run one `workflow_dispatch` of `deploy.yml` on `edge` and record the result in `deployment-manager`
- [ ] Port the App Engine cron schedule (`java-legacy:src/main/appengine/cron.yaml`) to Cloud Scheduler jobs on the
	`edge-loader` endpoints
- [ ] Re-enable the `push` trigger of `deploy.yml` for `edge`
- [ ] Add the `oracle` service from `feature/mcp`, renaming it to `{environment}-oracle` and `DATA_ENVIRONMENT`

# 2. Promote to `next` and `main`

Promote with merge commits, never a squash. Each promotion moves its branch from the `gae-deploy.yml` to the
`deploy.yml` triggers in the same commit, so the two workflows never deploy the same branch.

- [ ] Create the `next` secrets, runtime accounts, scheduler jobs and `data-next-{service}` GraphDB users, then promote
	`edge` → `next`
- [ ] Do the same for `main` with the `data-main-{service}` users, then promote `next` → `main`
- [ ] Repoint the Confluence Knowledge Hub Status block cards from `src/main/java/.../*.md` to
	`packages/loader/src/*/pipes/*.md`

# 3. Retire App Engine

- [ ] Delete the App Engine versions `main`, `next` and `work`, then disable the App Engine application
- [ ] Delete the `GCP_SA_KEY` and `GCP_PROJECT` repository secrets, then the `github` service account behind them
	(user key `3ef2b9b5…` from 2022; App Engine admin, Cloud Build editor, Cloud Scheduler admin, Storage admin and
	service account user roles)
- [ ] Delete the `server` service account (Secret Manager accessor, Storage object admin)
- [ ] Drop `roles/editor` and `roles/secretmanager.secretAccessor` from the default compute service account, and
	`roles/cloudtranslate.user` from `ec2u-data@appspot`
- [ ] Delete the `gae-standard`, `gcr.io`, `eu.gcr.io`, `us.gcr.io` and `asia.gcr.io` registries
- [ ] Delete the shared GraphDB user `data-server` and its secrets `gdb-server-usr`, `gdb-server-pwd`, with the legacy
	`googleai-key`
- [ ] Delete the secrets no pipe reads: `gemini-key`, `openai-key`, `events-turku-university-key`,
	`actors-entries-url`, `actors-terms-url`
- [ ] Disable the APIs only the Java stack used (`gcp-architect:prune`): App Engine Admin, App Engine reporting,
	Container Registry, Cloud Build, Datastore, Firestore, Cloud Translation, Vision, Natural Language
