# Issues and Solutions

## Missing Summary Field

**Issue:** The model was not generating summaries for subunits, even though they were clearly requested in the output
format.

**Example:** Testing with https://iii.dip.unipv.it/ showed units listed without summaries.

**Solution:**

- Made summary field REQUIRED in the schema: `required: ["name", "summary"]`
- Added explicit instruction in prompt: "Each subunit **MUST** include a summary (~100 chars)"
- Specified summary length requirement (~100 chars) with clear guidance on content

**Location:** `src/pipelines/leads/index.ts` (schema), `src/pipelines/leads/index.md` (prompt)

## Missing Homepage URLs

**Issue:** The model was not extracting homepage URLs even when they were clearly present on pages, resulting in missing
self-managed website links.

**Examples:**

- https://dbb.dip.unipv.it/it/ricerca/tematiche-di-ricerca-e-laboratori/bioinformatics-and-big-data/genomica-computazionale (
  missing link to https://lescailab.unipv.it/)
- https://iii.dip.unipv.it/it/ricerca/laboratori-di-ricerca (many labs with subdomain homepages not being extracted)

**Root Causes:**

1. Model wasn't fetching individual profile pages to look for homepage links
2. Confusion between profile URLs (institutional pages) and homepage URLs (self-managed sites)
3. Subdomains (e.g., lab-bioinfo.unipv.it) were being treated as profiles instead of homepages

**Solutions:**

- **Clarified definitions:** Made explicit distinction that subdomains are homepages, NOT profiles
    - Profile: page within parent unit's website structure (same domain and path hierarchy)
    - Homepage: subunit's own website (subdomain or independent domain)
- **Two-step process for finding homepages:**
    1. Check directory/listing pages for direct homepage links
    2. Fetch profile pages in parallel to find additional homepage links
- **Added explicit examples:** lab-bioinfo.unipv.it, vision.unipv.it (subdomains as homepages)
- **Made homepage optional but present:**
  `description: "The URL of the unit's self-managed website (omit if not available)"`

**Location:** `src/pipelines/leads/index.md` (Definitions and Guidelines sections)

## Structured Output Schema Issues

**Issue:** Homepage field was not being included in JSON output even though it was in the textual report.

**Root Cause:** No `required` array in the schema meant all fields were optional, so the model omitted fields
arbitrarily.

**Solution:**

- Added `required: ["name", "summary"]` to schema
- Made profile and homepage explicitly optional with "(omit if not available)" in descriptions
- This ensures model includes optional fields when data is available

**Location:** `src/pipelines/leads/index.ts:86`

## Profile vs Homepage Confusion

**Issue:** The model couldn't distinguish between institutional profiles and self-managed homepages.

**Solution:**

- **Clear definitions section** with explicit criteria:
    - Profile: within parent unit's website structure (same domain/path)
    - Homepage: subdomain or independent domain
- **Key insight:** Subdomains (e.g., lab.unipv.it) are homepages, not profiles
- **Three types for profiles:** dedicated, embedded, mentioned (for analyzing institutional pages)

**Location:** `src/pipelines/leads/index.md` (Definitions section)

## URL Requirements

**Issue:** Need to ensure at least one URL is present as evidence of online presence.

**Solution:**

- Requirement: "Each subunit MUST have at least one URL (profile or homepage)"
- Clarified that profile can be either:
    - A dedicated page for the subunit
    - A section where the subunit is mentioned alongside others

**Location:** `src/pipelines/leads/index.md` (Requirements section)

## Nested Subunits Not Reported

**Issue:** The model was not reporting nested subunits (subunits of subunits), even when clearly described on profile
pages.

**Examples:**

- https://dbbs.dip.unipv.it/it/ricerca/attivita-di-ricerca/linee-e-temi-di-ricerca/unita-di-neurodiagnostica (has 3
  sotto-unità)
- https://dbbs.dip.unipv.it/it/ricerca/attivita-di-ricerca/linee-e-temi-di-ricerca/unita-di-neurologia-clinica-e-riabilitativa (
  has nested subunits)
- https://dbbs.dip.unipv.it/it/ricerca/attivita-di-ricerca/linee-e-temi-di-ricerca/unita-di-neuropsichiatria-infantile (
  has nested subunits)

**Solution:** Made the task explicitly single-level:

- Added: "Report ONLY the immediate/direct subunits (one level down)"
- Added: "Do NOT include nested subunits of subunits - the pipeline will handle those recursively"
- This architectural choice delegates recursion to application code rather than the prompt

**Location:** `src/pipelines/leads/index.md` (Task section)

## Research Centers Being Excluded

**Issue:** Research centers (centri di ricerca/centri studi) were being excluded, incorrectly classified as external
collaborations.

**Example:** https://giurisprudenza.dip.unipv.it/it/ricerca/persone-e-network/gruppi-e-centri-di-ricerca lists multiple
research centers that were not being reported.

**Root Cause:** The definition of "NOT subunits" included "Coordinating research centers" which was too broad, causing
all research centers to be filtered out.

**Solution:**

- Explicitly added "Research centers (centri di ricerca/centri studi) **that are part of the unit**" to the list of
  structural subunits
- Added Italian terminology (laboratori, gruppi di ricerca, centri di ricerca/centri studi) for Italian websites
- Clarified "NOT subunits" to be more specific about external vs internal centers
- Added key distinction rule: "belonging to/part of" the unit → subunit; "collaborate with/participate in" → not a
  subunit

**Location:** `src/pipelines/leads/index.md` (Definitions section)

## Research Themes vs Actual Units

**Issue:** The model was reporting research themes/topics/areas as structural units instead of exploring them to find
the actual labs underneath.

**Example:** https://dbb.dip.unipv.it/it showed pages like "Bioinformatics and Big Data", "Neurofarmacologia" which are
thematic groupings, not actual labs. Each theme page contains links to actual laboratories (e.g., "Genomica
Computazionale" under "Bioinformatics and Big Data").

**Root Cause:** The model couldn't distinguish between thematic/topical organization pages and actual structural units.

**Solution:**

- **Added to "NOT subunits" list:** "Research themes, topics, or areas (thematic groupings that may contain labs but
  are not themselves organizational units)"
- **Added key distinctions:**
    - "Has dedicated members/space/PI → likely a unit; purely thematic/topical grouping → not a unit"
    - "If a page links to actual labs/groups underneath it, those linked labs are subunits, not the theme page itself"
- **Added exploration step:** "If pages appear to be research themes/topics rather than actual units, explore links
  within those pages to find actual labs/groups"
- **Added principle:** "Do NOT report thematic pages as units; explore them to find actual labs underneath"

**Location:** `src/pipelines/leads/index.md` (Definitions and Guidelines sections)

# Architectural Choices

## Two-Phase Pipeline

**Choice:** Separate analysis and structuring phases

**Rationale:**

- **Phase 1 (analyze):** Generate textual report with exploratory function calling
- **Phase 2 (structure):** Convert textual report to structured JSON
- Separation allows flexibility in output format and easier debugging

**Implementation:**

```typescript
export async function analyze(lead: Lead): Promise<string>

export async function structure(report: string): Promise<readonly Lead[]>
```

## Single-Level Extraction with Application-Level Recursion

**Choice:** Make the model report only direct subunits, handle recursion in application code

**Rationale:**

- Simpler prompt instructions (single responsibility)
- Better control over recursion depth and termination
- Easier to cache and optimize individual calls
- More predictable token usage

**Alternative Rejected:** Having the model recursively explore all nested levels in one call

- Would make prompt more complex
- Harder to control and debug
- Less predictable performance

## Profile and Homepage as Separate Optional Fields

**Choice:** Two optional URL fields instead of a single required URL

**Rationale:**

- Some units have only institutional profiles
- Some units have only self-managed homepages
- Many units have both
- Explicit separation makes the distinction clear and preserves both when available

**Implementation:** See `Lead` interface in `src/pipelines/leads/index.ts`

## Structured Definitions Section in Prompt

**Choice:** Separate "Definitions" section before "Requirements" and "Guidelines"

**Rationale:**

- Clear terminology upfront prevents confusion
- Provides reference point for rest of prompt
- Makes it easier to maintain consistency
- Separates "what things mean" from "what to do"

**Structure:**

1. Role/Input/Task - Context
2. Definitions - Terminology
3. Requirements - MUST statements
4. Guidelines - How-to guidance

## Explicit Empty List Handling

**Choice:** Allow and explicitly document empty list as valid output

**Rationale:**

- Some units genuinely have no subunits
- Makes it clear the model can stop exploring and return empty result
- Prevents false positives or forced extractions

**Implementation:** "If no direct structural subunits are found after thorough exploration, return an empty list."

# Key Learnings

1. **Schema requirements matter:** Without explicit `required` fields, models will omit fields unpredictably
2. **Subdomain confusion:** Subdomains need explicit clarification as homepages, not profiles
3. **Recursive vs iterative:** Delegating recursion to code is simpler than handling it in prompts
4. **Two-phase processing:** Separating exploration from structuring provides flexibility
5. **Explicit instructions:** "Check listing page THEN fetch profile pages" is clearer than "find all homepages"
6. **Documentation in descriptions:** Field descriptions like "(omit if not available)" guide model behavior
7. **Thematic vs structural distinction:** Models need explicit guidance to distinguish topical groupings from actual
   organizational units; require exploration step to find units within themes
