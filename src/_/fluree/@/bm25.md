# Model

A BM25 index is a **graph source**: a derived, standalone artefact built from a query over a source ledger, addressed
by the alias `<name>:<branch>` such as `test-search:main`. It is not part of the ledger it indexes, and it does not
participate in the ledger's transaction history.

The index is defined by an **indexing query** in FQL (JSON-LD) that selects both the documents to index and the text
properties to index for each one. The query must select `@id`.

```json
{
  "@context": { "ex": "http://example.org/" },
  "where": [{ "@id": "?x", "ex:name": "?name" }],
  "select": { "?x": ["@id", "ex:name"] }
}
```

# Creating an Index

Creation works over HTTP and from the CLI. Both routes reach the same server.

```bash
curl -X POST http://localhost:8090/v1/fluree/bm25/create \
  -H "Content-Type: application/json" \
  -d '{"name": "test-search", "ledger": "test:main", "query": { ... }}'
```

```bash
fluree bm25 create --name test-search --ledger test:main -f index-query.json
```

Configuration is small and mostly fixed:

| Field    | Default    | Notes                                                            |
|----------|------------|------------------------------------------------------------------|
| `name`   | required   | Graph-source name; must not contain a colon                      |
| `ledger` | required   | Source ledger alias, for example `test:main`                     |
| `query`  | required   | Indexing query in FQL/JSON-LD; must select `@id`                 |
| `branch` | `main`     | Branch of the index graph source                                 |
| `k1`     | `1.2`      | Term-frequency saturation; typical range 1.2 to 2.0              |
| `b`      | `0.75`     | Document-length normalisation, 0.0 to 1.0                        |

The CLI exposes the same fields as `--name`, `--ledger`, `--branch`, `--query`/`--query-file`, `--k1` and `--b`, plus
`--remote` to target a configured remote server and `--direct` to bypass the local server and work against storage
in process.

> [!NOTE]
> The analyser is not configurable. Fluree always applies its English pipeline: tokenisation, lowercasing, stopword
> filtering and stemming.

# Querying

Search is issued as an ordinary query against the **source ledger**, with a graph-source block that delegates to the
index. The `f:` namespace is `https://ns.flur.ee/db#`.

```json
{
  "@context": { "f": "https://ns.flur.ee/db#" },
  "from": "test:main",
  "select": ["?doc", "?score"],
  "where": [{
    "f:graphSource": "test-search:main",
    "f:searchText": "Alice",
    "f:searchLimit": 10,
    "f:searchResult": { "f:resultId": "?doc", "f:resultScore": "?score" }
  }]
}
```

> [!IMPORTANT]
> This is available **only through FQL/JSON-LD**. The SPARQL parser does not recognise the `f:` search block, so
> full-text search cannot be expressed in a SPARQL query and needs a separate, FQL-shaped code path alongside any
> `sparql-http-client` usage.

A standalone `fluree-search-httpd` service also exposes the index over `POST /v1/search` for deployments that prefer
a dedicated search endpoint.

# Maintenance

Indexes are **not** updated automatically when the source ledger changes.

- **Staleness**: `fluree bm25 list` reports `INDEX_T` against `LEDGER_T` and a `STALE` column; `--stale` filters to
  stale indexes only
- **Sync**: `fluree bm25 sync --index test-search:main`, or `POST /v1/fluree/bm25/sync`. Incremental where possible,
  re-indexing only subjects changed since the stored watermark, falling back to a full rebuild when needed, and a
  no-op when already current. `--t <T>` syncs through a specific source `t` instead of the head
- **Automatic sync**: starting the server with `--bm25-auto-sync` syncs on every source commit, removing the need for
  a maintenance job
- **Drop**: `fluree bm25 drop --index test-search:main --force` retracts the index and deletes its snapshots. The
  `--force` flag is required

# Verified Behaviour

Checked against `fluree/server:4.1.5` on the local instance, indexing `ex:name` over `test:main`:

```json
{"graph_source_id":"test-search:main","doc_count":1,"term_count":1,"index_t":2,
 "index_id":"baghybqabciqpoohd2wbx6bmvjalhh4vll5sdmvrrftt3m4kywci4hd65rzfhuwy"}
```

Creation over HTTP returned `201`. `fluree bm25 list` then reported `test-search | main | test:main | 2 | 2 | no`, and
the FQL search for `"Alice"` returned `[["http://example.org/alice", 0.28768207245178085]]`.

`POST /v1/fluree/bm25/create` with an empty body returns `400`, confirming the endpoint exists rather than falling
through to the 404 handler.
